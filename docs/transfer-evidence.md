# Backup, restore and CSV export (issue #5)

- User starts transfer from **Your data** on home screen. Export writes a temporary protected file, then exposes `ShareLink`. No automatic sync or network client exists in app or domain package. Destination chosen by user in iOS share sheet; external share destinations can move content off-device, so UI warns that backup bytes are readable by anyone holding the file. Temporary files can persist inside app container until system cleanup; delete via system storage controls if needed.
- Restore uses iOS document picker scoped access and parses a versioned JSON envelope (`version: 1`) before showing project/photo counts, matching project IDs, and overwrite warning. User must tap **Replace workspace**. Future/older versions, malformed JSON, invalid records, missing/duplicate/orphan photo data all fail before touching live store. Existing projects not in backup are removed on confirmed replacement, not merged.
- Restore stages records and photo bytes in adjacent same-volume directory, then swaps roots. If stage fails, live directory stays untouched; if final move fails, rollback moves old root back. An abrupt process kill between directory moves can leave old data under a `.previous-*` sibling; no background cleanup removes it. Recovery must inspect sibling before changing local files. Disk-space requirement: enough free space for full backup contents plus current workspace during restore.
- LocalProjectStore sets iOS complete file protection and excludes its root from device/iCloud backups. Staging store gets same protection/exclusion; exported temporary files get complete file protection. Photo import uses scoped PhotosPicker or camera, without blanket library access. Restore uses security-scoped document access and closes scope in `defer`.
- CSV summarizes projected step status and part stock, not manufacturer-approved safety measurements. Unknown stays `unknown`; overspent stock stays `conflict`. RFC 4180 escaping protects commas, double quotes and line breaks; CSV is plaintext shared only by user action.
- No accounts, ads, telemetry, network requests, Contacts, location, microphone or photo-library enumeration. `scripts/check_zero_network.sh` scans app/UITests/package source with an empty allowlist, and `scripts/check_native_only.sh` rejects hybrid framework manifests. Linux SwiftPM tests validate backup/photo round trip, conflict preview, stale preview rejection, older/future/malformed rejection, replacement/old-photo removal and CSV conflict escaping. Apple simulator CI is required for actual SwiftUI build and UI journey; Linux cannot prove iOS compilation or share sheet presentation.
