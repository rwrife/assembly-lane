# Assembly Lane — Release Runbook (TestFlight)

Issue #7 pipeline: a green `main` + a version tag produces a signed TestFlight
build via the App Store Connect API. Ported from the proven
rwrife/cook-console template (also green in rise-log, split-slip, catch-tally).
No fastlane/npm/gem is pinned — the pipeline is
`.github/workflows/release.yml` plus `Tools/asc_jwt.rb` (dependency-free ES256
JWT minter using the runner's stock openssl/ruby).

## Secrets (names only — values must never appear in any log)

| Secret | Purpose |
|---|---|
| `ASC_KEY_ID` | App Store Connect API key ID (JWT `kid`) |
| `ASC_ISSUER_ID` | ASC issuer UUID (JWT `iss`) |
| `ASC_KEY_P8` | PKCS#8 EC private key body; written to `$RUNNER_TEMP/asc-api-key.p8` (mode 600), deleted in an `always()` step |
| `ASC_TEAM_ID` | Developer team for automatic signing (`DEVELOPMENT_TEAM`) |

The workflow's first step verifies each secret NAME is present (presence only,
never a value). Secret variables are consumed as env inputs only, never
interpolated into echo statements.

## Versioning

- `VERSION` (repo root) holds the marketing version `x.y.z`.
- `Scripts/check_release.py` (Linux CI + macOS CI + release job) fails if
  `MARKETING_VERSION` ever drifts from `VERSION`.
- **Build number = the Actions run number** of the release workflow —
  strictly monotonic, never recycled in ASC.
- The tag must equal `v$VERSION`. Mismatch = instant failure, no upload.

## Icon

Single 1024×1024 universal master at `AppStore/icon.png`, mirrored byte-identical
into `App/Assets.xcassets/AppIcon.appiconset/AppIcon.png`. Generated by the
`gpt-image-2.5-flare` model through the OpenAI Images API (spark-media image
route, 2026-10-16) from the fleet icon brief plus repo-derived subject analysis:
hex bolt + loose screws in sorting compartments with a step-progress path on a
teal→orange gradient. Measured properties: PNG RGB color type 2 (no alpha
channel → no transparency), 1024×1024, edge-to-edge gradient reaching all four
corners, no border frame, no baked corner radius, no lettering. `Scripts/
check_release.py` re-verifies size, opacity, catalog wiring and byte-identity
on every CI run; Apple CI additionally asserts `Assets.car` exists in the
signed archive (Xcode 26 single-size icons do not write `CFBundleIconName`).

## Cutting a release

1. On green `main`: bump `VERSION` (and `MARKETING_VERSION` in
   `AssemblyLane.xcodeproj`) in a PR, merge when green.
2. `git tag v$VERSION && git push origin v$VERSION` (or dispatch
   `Release (TestFlight)` with the matching version input).
3. Watch `Actions → Release (TestFlight)`: pinned Xcode 26.0.1 selection →
   gates → signed archive (asserts archive `UIDeviceFamily == [1]`,
   `CFBundleIdentifier == com.infinityball.assemblylane`, `Assets.car`
   present) → export `method=app-store-connect`, `destination=upload` →
   ASC polling until `VALID`/`COMPLETE` → build attached to the **Internal**
   beta group with notes → GitHub release → key material deleted.
